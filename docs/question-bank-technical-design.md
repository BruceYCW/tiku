# 题库系统初始化技术设计

> 文档状态：Draft 0.2
> 适用分支：`codex/question-bank-init`
> 更新时间：2026-09-05

## 1. 文档目标

本文档用于建立题库系统的第一版技术基线，明确初始化阶段的业务范围、模块边界、数据模型、接口约定和实施顺序。后续代码实现、数据库迁移和测试应以本文档为起点；未决项在评审后更新，不在实现中隐式拍板。

### 1.1 项目技术选型须知

以下约束是本项目的硬性要求，后续开发、技术讨论和代码生成均须遵守：

- 系统必须支持单机本地部署，安装后可在没有云服务的环境中运行。
- 第一阶段不得依赖 Redis、对象存储、Elasticsearch/OpenSearch、消息队列或其他需要独立部署的中间件。
- 主数据使用本地 SQLite 数据库文件；题目附件和导入文件使用本地文件目录。
- 缓存、异步任务和定时任务优先使用进程内实现；不能因引入缓存而增加部署组件。
- 数据库文件和本地数据目录属于可复制、可备份资产，但不得提交到 Git 仓库。
- 如果未来需要替换基础设施，必须保持领域模型和 API 兼容，并提供迁移工具；不得直接把云端服务写成运行前提。

## 2. 目标与范围

### 2.1 第一阶段目标

- 支持 PDF、图片和 `.docx` 试卷导入，其中 PDF 和图片默认执行本地 OCR。
- 支持导入材料的页面预览、自动切题、识别结果校对、手动选区切题和确认入库。
- 支持课本、章节、知识点的层级维护，并将题目自动分类结果与人工确认结果分开保存。
- 支持题库、分类和知识点的基础管理。
- 支持单选题、多选题、判断题和简答题。
- 支持题目草稿、发布、下线和归档等生命周期管理。
- 支持按课本、章节、知识点、题型、难度、来源试卷和关键字检索。
- 支持按题型、题量和难度分布自动组卷，并支持组卷后预览、替换、排序和手动编辑。
- 支持将试卷按常见考试试卷样式排版并导出 PDF。
- 支持用户、角色、权限和操作审计。
- 支持导入任务、组卷任务和 PDF 导出任务的进度查询。

### 2.2 暂不纳入第一阶段

- 在线考试监考、反作弊和复杂阅卷策略。
- 云端 OCR、云端大模型分类或任何必须联网才能完成的识别能力。
- AI 自动出题或自动判分。
- 多租户计费、组织结算和开放平台。
- 富媒体编辑器之外的独立素材管理中心。

## 3. 用户角色

| 角色 | 主要能力 |
| --- | --- |
| 系统管理员 | 用户、角色、题库和全局配置管理 |
| 题库管理员 | 创建和维护题库、分类、知识点及题目 |
| 审核员 | 审核、发布、下线题目，查看审计记录 |
| 教师/出题人 | 在授权题库中创建题目、维护个人草稿 |
| 学习者 | 查询可见题目、参与练习、提交作答 |

权限应同时绑定“动作”和“资源范围”。例如，用户可以拥有 `question:read`，但只允许访问指定题库；服务端不得仅依赖前端隐藏按钮实现授权。

## 4. 总体架构

第一阶段采用模块化单体架构，按领域拆分模块，使用 REST API 对外提供能力。这样可以保持部署和事务简单，同时为后续拆分服务保留边界。

```text
Web / Mobile Client
        |
   API / Auth
        |
  +-----+-------------------------------+
  | 题库 题目 练习 组卷 用户 权限 审计 |
  +-----+-------------------------------+
        |
  SQLite 文件数据库 + 本地文件目录
```

### 4.1 当前第一阶段技术栈

| 层次 | 推荐方案 | 说明 |
| --- | --- | --- |
| 前端 | 原生 HTML/CSS/JavaScript | 第一阶段管理台零构建依赖，浏览器直接访问本地服务 |
| 后端 | Node.js 22+ 原生 HTTP | 模块化单体，使用内置 `node:sqlite`，不引入外部运行时中间件 |
| 主数据库 | SQLite 3 | 单文件、零服务、便于本地部署和自行备份拷贝 |
| 缓存 | 不设置外部缓存 | 使用进程内缓存或直接查询 SQLite |
| PDF/图片处理 | 本地 `pdftotext`、Tesseract 适配器 | 文本 PDF 优先提取；扫描 PDF/图片调用本机 OCR，未安装时保留待处理状态 |
| DOCX 处理 | Node.js 标准 ZIP/XML 解析 | 读取文档段落；复杂表格、图片和版式由后续适配器补齐 |
| OCR | 本地 Tesseract；后续可接 PaddleOCR 本地模型 | OCR 在本机执行，不上传原始试卷 |
| PDF 排版 | 当前为最小本地 PDF 生成器 | 当前只验证快照和文件链路；中文字体、图片、分页等进入后续排版适配阶段 |
| 文件存储 | 本地文件目录 | 存放原始试卷、页面图像、裁剪片段、附件和导出文件 |
| 部署 | 本地进程或单容器 | 默认不要求 Docker Compose 和外部服务 |

SQLite 使用 JSON 文本字段保存题型扩展内容，使用普通索引和 SQLite FTS5 满足第一阶段检索需求。当前实现不依赖 npm 包管理器即可启动；如后续引入库，必须以本地可安装、可离线运行且不需要独立部署中间件为前提。技术栈发生调整时，应同步更新本文档和部署说明。

OCR 引擎和模型文件必须作为本地安装包、应用资源或明确的离线初始化资源管理。默认运行流程不得调用外部 API，不得将原始试卷、OCR 文本或题目内容上传到第三方服务。OCR 引擎可以通过本地进程调用，但必须由应用统一管理超时、错误和临时文件。

### 4.2 本地部署方案

默认目录结构如下，根目录可通过 `TIKU_DATA_DIR` 配置：

```text
data/
  tiku.db                 # SQLite 主数据库
  uploads/                # 题目图片、附件和导入原文件
  imports/                # 导入任务中间产物：页面图像、OCR 结果和题目片段
  exports/                # 导出文件和导入错误报告
  backups/                # 本地备份文件
  models/                 # 可选的本地 OCR 模型文件
```

应用启动时自动创建缺失目录和数据库，执行未完成的数据库迁移后再提供服务。除应用本身外，不要求用户启动 Redis、数据库服务、对象存储或搜索服务。

SQLite 连接使用 WAL 模式、外键约束和合理的忙等待时间；第一阶段按单机、低并发场景设计，写入操作通过事务串行化。若未来出现多实例部署、持续高并发写入或大规模全文检索需求，再评估迁移到服务型数据库，但这不是当前部署前提。

### 4.3 数据库复制与备份

用户可以自行拷贝 `data/tiku.db` 完成数据迁移或备份，但必须遵守以下规则：

- 最简单可靠的方式是停止应用后复制数据库文件及 `data/uploads/`、`data/exports/` 目录。
- 应用运行期间不得直接只拷贝 SQLite 主文件，尤其是在 WAL 模式下，否则可能遗漏 `-wal` 和 `-shm` 文件中的已提交数据。
- 后续应提供 `backup` 命令或管理接口，使用 SQLite 在线备份机制生成一致性副本，再将副本拷贝到其他目录或设备。
- 恢复时先停止应用，将备份文件放回数据目录，再启动应用执行迁移和健康检查。
- 备份文件不得进入 Git；建议按日期保留多个副本，并定期实际打开副本验证可恢复性。

本地附件不在 SQLite 文件内，恢复数据库时必须同时复制对应的 `uploads/` 目录；导出文件和错误报告可按需复制，不作为主数据恢复的必要条件。

## 5. 模块划分

### 5.1 题库模块

负责题库、课本、章节和知识点的树形组织。题库删除建议采用逻辑删除；已经被试卷或作答记录引用的题库只能归档，不能物理删除。课本和知识点支持别名、编码和适用年级，便于不同试卷中的名称归一化。

### 5.2 试卷导入模块

负责原始 PDF、图片和 `.docx` 文件的接收、解析、OCR、页面切割、题目候选生成、知识点候选分类和人工校对。导入模块只生成“待确认的导入草稿”，不得绕过预览和确认步骤直接写入正式题库。

### 5.3 题目模块

负责题目内容、选项、答案、解析、标签、难度、来源和版本。题型使用枚举加结构化内容，避免为每个题型创建一套完全独立的表。题目应保留来源试卷、来源页码和原始裁剪图，便于追溯识别错误。

### 5.4 题目审核与发布模块

负责题目状态流转、审核意见和版本冻结。只有已发布版本能被练习和组卷读取；编辑已发布题目时创建新草稿版本，不直接覆盖线上版本。导入校对确认和题目正式发布是两个步骤，确认只代表内容进入题库草稿，不代表立即对学习者可见。

### 5.5 试题检索模块

负责按课本、章节、知识点、题型、难度、标签、来源和关键字组合查询题目。检索结果默认只返回已发布题目；管理员和校对人员可以在授权范围内检索草稿及导入候选。

### 5.6 练习模块

负责题目抽取、作答提交、判分和错题记录。第一阶段只实现客观题自动判分，简答题保留人工评分状态。

### 5.7 组卷模块

负责组卷规则、候选题筛选、题目抽取、人工替换、题目排序、分值计算、版式预览和 PDF 导出。试卷引用题目时保存题目版本快照，后续题目修改不能改变已经发布的试卷。

### 5.8 用户、权限与审计模块

负责认证、RBAC、资源范围和关键操作记录。审计记录只追加，不提供普通用户修改能力。

## 6. 核心数据模型

以下字段为逻辑模型，实际建表时统一增加 `id`、`created_at`、`updated_at`；涉及删除的实体增加 `deleted_at`。

### 6.1 主要实体

| 实体 | 关键字段 | 关系 |
| --- | --- | --- |
| `question_bank` | `name`, `description`, `status`, `owner_id` | 一个题库包含多个分类和题目 |
| `textbook` | `bank_id`, `name`, `subject`, `grade`, `edition` | 题库中的课本，关联章节和知识点 |
| `textbook_chapter` | `textbook_id`, `parent_id`, `name`, `sort_order` | 课本章节树，根节点 `parent_id` 为空 |
| `category` | `bank_id`, `parent_id`, `name`, `sort_order` | 分类可无限层级，根节点 `parent_id` 为空 |
| `knowledge_point` | `bank_id`, `textbook_id`, `chapter_id`, `parent_id`, `name`, `aliases` | 知识点可树形组织，归属课本章节 |
| `question` | `bank_id`, `type`, `status`, `difficulty`, `current_version_id` | 题目的稳定身份 |
| `question_version` | `question_id`, `version_no`, `content`, `answer`, `analysis`, `created_by` | 题目的不可变内容版本 |
| `question_source` | `import_job_id`, `page_no`, `crop_path`, `source_hash`, `source_text` | 题目的原始试卷来源和裁剪图，可一题多来源 |
| `question_tag` | `question_id`, `tag_id` | 题目与标签多对多 |
| `question_knowledge_point` | `question_id`, `knowledge_point_id` | 题目与知识点多对多 |
| `import_job` | `file_path`, `file_type`, `status`, `progress`, `created_by` | 一次试卷导入任务 |
| `import_page` | `job_id`, `page_no`, `image_path`, `ocr_text`, `ocr_blocks`, `status` | 页面图像和 OCR 结果 |
| `import_question_candidate` | `job_id`, `page_start`, `page_end`, `crop_path`, `content`, `confidence`, `status` | 自动切题生成的待校对候选 |
| `candidate_knowledge_point` | `candidate_id`, `knowledge_point_id`, `source`, `confidence`, `confirmed` | 候选知识点及自动/人工来源 |
| `paper_template` | `name`, `page_size`, `margin_config`, `header_config`, `footer_config` | 可复用的试卷版式模板 |
| `paper` | `name`, `status`, `rule_config`, `template_id`, `total_score`, `published_at` | 组卷规则和试卷状态 |
| `paper_question` | `paper_id`, `question_version_id`, `sort_order`, `section_no`, `score`, `source` | 试卷题目版本关联及人工调整来源 |
| `paper_snapshot` | `paper_id`, `snapshot_json`, `pdf_path`, `created_at` | PDF 导出时的不可变试卷快照 |
| `practice_record` | `user_id`, `paper_id`, `status`, `score` | 一次练习或考试记录 |
| `answer_record` | `practice_id`, `question_version_id`, `answer`, `score`, `grading_status` | 保存作答时使用的版本 |
| `audit_log` | `operator_id`, `action`, `resource_type`, `resource_id`, `before_data`, `after_data` | 关键操作追加记录 |

### 6.2 题目内容结构

`question_version.content` 使用 JSON 结构保存题干及题型专属内容，服务端按题型校验。示例：

```json
{
  "stem": "下列哪项属于 ...？",
  "options": [
    {"key": "A", "text": "选项一"},
    {"key": "B", "text": "选项二"}
  ],
  "attachments": []
}
```

`answer` 与 `analysis` 必须和题目内容版本一起保存。对学习者的查询接口默认不返回标准答案；答案、解析和审核信息必须由服务端根据权限决定是否返回。

### 6.3 导入候选数据

导入候选不能直接复用正式题目表。`import_job` 保存原始文件和任务状态，`import_page` 保存页级处理中间结果，`import_question_candidate` 保存一次自动切题结果及人工修改结果。候选确认后，系统在事务中创建 `question`、`question_version`、`question_source` 和知识点关联，并记录候选到正式题目的映射。

候选内容至少包括题号、题型候选、题干、选项、答案、解析、难度候选、知识点候选、来源页码和裁剪区域。每个字段应记录 `auto_value`、`confirmed_value` 和 `source`，其中 `source` 可为 `ocr`、`parser`、`rule`、`manual`，便于定位错误和统计人工修改率。

### 6.4 组卷数据

`paper.rule_config` 保存题型、题量、分值、难度分布、知识点范围、课本范围、是否允许重复、题目排序方式等约束。自动组卷只选择已发布题目版本，并在生成时保存候选池和随机种子，确保可以复现一次组卷结果。

`paper_question.source` 区分 `auto`、`manual_replace`、`manual_add` 和 `manual_remove`。组卷预览阶段的每次调整都写入操作记录；导出 PDF 时生成 `paper_snapshot`，确保再次导出不会因题库内容变化而改变已确认试卷。

### 6.5 题型约束

| 题型 | 内容要求 | 答案要求 | 第一阶段判分 |
| --- | --- | --- | --- |
| `single_choice` | 至少 2 个选项，选项 key 唯一 | 一个选项 key | 自动 |
| `multiple_choice` | 至少 2 个选项，选项 key 唯一 | 去重后的选项 key 集合 | 自动，默认全对得分 |
| `true_false` | 题干 | `true` 或 `false` | 自动 |
| `short_answer` | 题干，可带评分要点 | 文本或评分要点 | 人工/待评分 |

## 7. 状态与不变量

题目状态建议为：`draft -> pending_review -> published -> offline -> archived`。允许 `pending_review -> draft` 退回修改，允许 `published -> offline` 下线；归档后不可直接恢复编辑。

导入任务状态建议为：`uploaded -> parsing -> ocr_processing -> cutting -> classifying -> waiting_review -> confirmed -> completed`，异常统一进入 `failed`，人工取消进入 `cancelled`。只有 `waiting_review` 状态允许人工校对，只有 `confirmed` 状态允许正式入库。

组卷状态建议为：`draft -> generating -> preview -> editing -> confirmed -> exporting -> exported`，导出失败进入 `export_failed`。已确认或已导出的试卷不能直接修改，修改时创建新的试卷草稿或新版本。

必须保证以下不变量：

- 题目发布前必须通过题型校验、必填字段校验和关联资源校验。
- 同一题目的版本号严格递增，版本内容发布后不可变。
- 组卷和作答始终引用具体 `question_version`，不能只引用题目 ID。
- 题库、分类、知识点的资源范围由服务端校验，禁止越权访问。
- 导入任务重复执行时使用幂等键，避免重复创建题目。
- 原始文件、页面、题目候选和正式题目之间必须可追溯；人工确认值不得覆盖原始 OCR 结果。
- 自动切题、知识点分类和难度推断均属于候选结果，不能在无人确认时直接发布。
- 组卷规则无解时返回缺口信息，例如某题型可用数量不足或难度分布无法满足，而不是静默放宽规则。
- 手动替换题目必须重新校验题型、难度、知识点范围、重复题和总分。
- PDF 导出使用固定的试卷快照，题目库后续变更不得影响已导出的文件。
- 删除题目不会删除历史试卷和作答记录。

## 8. API 初稿

API 前缀统一为 `/api/v1`，响应使用统一结构：

```json
{
  "code": "OK",
  "message": "",
  "data": {},
  "requestId": "..."
}
```

建议的首批接口：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/question-banks` | 分页查询题库 |
| `POST` | `/question-banks` | 创建题库 |
| `GET` | `/question-banks/{bankId}/questions` | 条件检索题目 |
| `GET` | `/question-banks/{bankId}/textbooks` | 查询课本、章节和知识点树 |
| `GET` | `/questions/search` | 按课本、章节、知识点、题型、难度和关键字检索 |
| `POST` | `/question-banks/{bankId}/questions` | 创建题目草稿 |
| `PUT` | `/questions/{questionId}/draft` | 编辑草稿版本 |
| `POST` | `/questions/{questionId}/submit-review` | 提交审核 |
| `POST` | `/questions/{questionId}/publish` | 发布审核通过版本 |
| `POST` | `/questions/{questionId}/offline` | 下线题目 |
| `GET` | `/questions/{questionId}/versions` | 查看版本列表 |
| `POST` | `/imports/papers` | 上传 PDF、图片或 `.docx` 并创建试卷导入任务 |
| `GET` | `/imports/{jobId}` | 查询导入进度和错误报告 |
| `GET` | `/imports/{jobId}/pages/{pageNo}` | 查看页面图像、OCR 块和识别结果 |
| `GET` | `/imports/{jobId}/candidates` | 查询自动切题和分类候选 |
| `PUT` | `/imports/{jobId}/candidates/{candidateId}` | 人工修改题目候选或知识点 |
| `POST` | `/imports/{jobId}/candidates/{candidateId}/crop` | 保存手动选区并重新切题/OCR |
| `POST` | `/imports/{jobId}/confirm` | 确认候选并导入题库草稿 |
| `POST` | `/papers/generate` | 根据组卷规则自动生成试卷草稿 |
| `GET` | `/papers/{paperId}/preview` | 预览组卷结果和题目统计 |
| `POST` | `/papers/{paperId}/questions/{paperQuestionId}/replace` | 按约束替换试卷题目 |
| `POST` | `/papers/{paperId}/confirm` | 确认试卷快照 |
| `POST` | `/papers/{paperId}/export-pdf` | 创建 PDF 导出任务 |
| `GET` | `/exports/{jobId}` | 查询 PDF 导出进度和文件 |
| `GET` | `/papers/{paperId}` | 查询试卷及题目快照 |
| `POST` | `/practices` | 创建练习 |
| `POST` | `/practices/{practiceId}/answers` | 提交作答 |

列表接口必须支持 `page`、`pageSize`、`sort` 和明确的过滤参数；详情接口根据调用者权限裁剪答案、解析及内部字段。

## 9. 试卷导入设计

### 9.1 支持格式与预处理

第一阶段必须支持以下输入：

| 格式 | 处理方式 | 说明 |
| --- | --- | --- |
| PDF | 判断文本型或扫描型；文本型直接解析，扫描型逐页转图片后本地 OCR | 保留原始 PDF、页码和页面图像 |
| 图片 | 支持 PNG、JPG、JPEG，逐张执行本地 OCR | 支持旋转、裁剪、去噪和分辨率校验 |
| `.docx` | 读取段落、表格、图片和分页信息 | 优先使用文档结构解析，图片内容仍需本地 OCR |

文件上传后生成 `import_job`，原文件保存到本地 `imports/` 目录并计算 SHA-256。相同文件在相同题库和导入配置下重复上传时，应提示已有任务或复用已完成结果，避免重复处理和重复入库。

### 9.2 本地 OCR 流程

```text
原始文件
  -> 格式识别与安全校验
  -> 页面渲染/文档解析
  -> 图像预处理（旋转、去噪、二值化、分辨率调整）
  -> 本地 OCR
  -> OCR 文本与版面块
  -> 题目切分
  -> 题型/知识点候选分类
  -> 人工预览与校对
  -> 确认后写入题库草稿
```

本地 OCR 优先采用支持中文的 PaddleOCR 本地模型，Tesseract 作为轻量或兼容性备选。应用必须展示 OCR 置信度、识别文本和对应页面区域；低置信度文本、表格、公式和复杂排版应标记为需要重点校对。OCR 失败时保留页面图像并允许人工选区重新识别或直接手工录入。

### 9.3 自动切题

自动切题采用“规则优先、版面辅助、人工修正”的组合方式：

- 从 OCR 文本中识别题号模式，例如阿拉伯数字、括号题号、选择题选项标记和大题编号。
- 结合 OCR 坐标、行间距、字体区域、页面栏布局和题号顺序判断题目边界。
- 将题干、选项、题目图片、答案解析等相邻内容合并为一个候选题。
- 对跨页题目自动合并，并标记跨页来源；无法可靠判断时拆分为待确认候选。
- 为每个候选保存页面范围和矩形区域，可在预览中拖动上、下边界调整切割范围。

前端导入校对页面应支持：原始页面图像与识别文本并排展示、候选题列表、选中候选高亮、题目边界拖拽、手动框选新题、手动划线标记题目上下边界、合并候选、拆分候选、删除候选和重新 OCR。手动选区至少保存页码、坐标、旋转角度和裁剪图路径，便于重复处理。

### 9.4 知识点自动分类

知识点分类采用本地规则和本地模型的可替换接口，不将分类能力绑定到云端服务。分类输入包括题干、选项、解析、课本、章节、历史标签和题目来源；输出包括候选知识点、置信度、匹配依据和建议课本章节。

分类策略按以下顺序执行：

1. 使用课本章节和知识点别名词典进行关键词、短语和规则匹配。
2. 使用本地轻量文本分类模型进行补充推荐。
3. 按置信度排序展示候选，并允许人工选择、取消或新增知识点。

自动分类不能绕过人工确认。人工选择的知识点保存为 `confirmed=true`，后续检索和组卷默认使用确认结果；自动候选仅用于提示和后续模型评估。

### 9.5 人工校对与确认入库

校对工作台至少提供以下能力：修改题干和选项、调整题型、补充答案和解析、设置难度、选择课本章节和知识点、修正题目边界、查看原图、撤销/重做和保存草稿。系统应标记被人工修改过的字段，并在确认前显示待处理的低置信度项和必填项缺失项。

确认入库前执行题型校验、题号冲突检查、题目重复检查、知识点存在性检查、附件路径检查和题库权限检查。确认操作应显示成功数量、跳过数量和失败数量；失败题目不能影响其他合法候选入库，并应生成可下载的错误报告。

确认入库创建题目草稿，不直接发布。题目正式发布仍需经过题目审核流程。导入原文件、页面图像、OCR 文本、候选数据和正式题目之间必须可以相互跳转。

## 10. 试题检索设计

### 10.1 检索条件

题目检索至少支持以下条件的组合：题库、课本、版本/版次、学科、年级、章节、知识点及其子节点、题型、难度、标签、来源试卷、题目状态、创建人和关键字。课本和知识点筛选应支持“包含下级节点”，例如选择某章时同时检索该章下所有知识点题目。

### 10.2 检索实现

结构化条件使用 SQLite 普通索引和关联表查询；题干、选项、解析和标签关键字使用 SQLite FTS5。检索索引只收录有权限访问的题目，结果按相关度、难度、更新时间或随机种子排序。详情页提供来源页码和原始裁剪图入口，帮助用户判断题目是否适合使用。

检索接口必须支持分页、稳定排序、条件回显和空结果原因提示。组卷候选池复用同一套检索条件，并额外排除已选题、已使用题和不符合版本状态的题目。

## 11. 组卷与 PDF 导出设计

### 11.1 组卷规则

组卷页面允许用户设置试卷名称、题型顺序、每种题型题量、每题分值、总分、难度分布、课本/章节/知识点范围、是否允许重复、题目排序方式和备用题数量。难度分布既支持数量比例，也支持固定数量，例如简单 10 题、中等 15 题、困难 5 题。

自动组卷先按规则构造候选池，再按题型、难度、知识点覆盖和去重要求抽取题目。题型、题量、总分和不可重复属于硬约束；知识点覆盖、难度比例和题目均衡性可配置为硬约束或软约束。生成结果应显示规则满足情况、知识点覆盖统计、难度统计、总分和未满足约束。没有足够候选时，系统必须明确指出缺口，并由用户选择调整规则或进入人工编辑，不得静默降低要求。

### 11.2 预览与手动调整

组卷预览显示完整试卷、题目来源、知识点、难度、分值和当前题号。用户可拖拽排序、删除题目、从候选池添加题目、按同类约束替换题目、修改分值、调整题型分组和编辑试卷标题说明。

替换操作默认只展示满足原题型、题库范围、课本/知识点范围、难度和未重复约束的题目；用户明确切换为“放宽条件”后才能查看其他候选，并显示被放宽的条件。每次替换后实时重新计算总分、题量、难度分布和知识点覆盖。

### 11.3 常见试卷样式与 PDF

PDF 导出使用本地排版引擎生成，不依赖在线转换服务。版式模板至少支持纸张大小（默认 A4）、页边距、页眉、页脚、试卷标题、考试信息栏、题型标题、题号、选项缩进、分值、答题区域、页码和分页规则配置。

排版要求：题目不得被错误截断；题干与选项尽量保持在同一页；跨页时重复必要的题号或题型标题；图片按最大宽高约束等比例缩放；表格、公式和中文字体正确嵌入；页眉页脚不覆盖正文；导出后进行 PDF 页数、字体、图片和文本可读性检查。

默认提供“教师版试卷”和“参考答案/解析版”两种导出模式，答案版必须经过权限校验。导出前生成 `paper_snapshot`，保存最终题目版本、排序、分值、版式配置和导出文件路径。

## 12. 导入导出通用约束

文件大小、页数、图片分辨率、附件类型和本地处理超时时间需要配置上限。导入、OCR、切题、分类和 PDF 导出均采用进程内任务队列或受控线程池执行，不引入消息队列。任务进度写入 SQLite，应用重启后可将中断任务标记为可恢复或失败。

导入文件、错误报告和 PDF 文件属于受控本地资源，下载前进行权限检查。临时页面图像和 OCR 中间产物按保留策略清理，但正式题目的来源裁剪图和导入原文件在题目仍被引用时不得删除。

## 13. 安全与可靠性

- 使用短期访问令牌和可撤销的刷新令牌；密码只保存强哈希结果。
- 所有写接口执行服务端参数校验、资源授权和审计。
- 题干、解析和附件展示时进行 XSS 防护；富文本采用白名单过滤。
- 数据库使用迁移工具管理结构变更，生产环境禁止手工改表。
- 关键写操作使用事务；导入、导出、批量发布使用异步任务。
- 记录 `requestId`、操作者、资源 ID、耗时和错误码，便于排查。
- SQLite 数据库和本地附件至少执行每日备份，并定期验证恢复可用性。
- 日志、令牌、数据库备份和导入文件均保存在本地受控目录，不默认上传第三方服务。

## 14. 测试策略

- 单元测试：题型校验、答案规范化、客观题判分、状态流转。
- 集成测试：权限过滤、数据库迁移、版本发布、试卷快照、导入任务和本地文件目录。
- 导入测试：PDF 文本页、扫描 PDF、多页图片、旋转图片、复杂 `.docx`、跨页题目、选区重切、OCR 低置信度和重复文件。
- 检索测试：课本章节级联、知识点子节点、组合过滤、FTS5 关键字、权限隔离和分页稳定性。
- 组卷测试：题型/题量约束、难度分布、知识点覆盖、无解规则提示、手动替换、重复题校验和快照一致性。
- PDF 测试：A4 页面、中文字体、分页、长题干、图片、表格、公式、答案版权限和导出后可读性。
- API 测试：成功响应、参数错误、未登录、无权限、资源不存在和并发更新。
- 回归重点：已发布题目编辑不影响线上版本；历史作答能正确展示；重复导入不产生重复数据；已确认试卷不受题库后续修改影响。

## 15. 初始化实施顺序

1. 确认课本/章节/知识点目录、题型规范、PDF 版式、数据目录和本地 OCR 安装方式，保持本地零中间件约束。
2. 初始化项目骨架、代码规范、配置分层、SQLite 数据库迁移、任务状态表和健康检查。
3. 实现用户、角色、资源权限和审计基础能力。
4. 实现题库、课本、章节、知识点、分类和标签管理。
5. 实现本地文件接收、PDF/图片/`.docx` 预处理和页面预览。
6. 实现本地 OCR、自动切题、候选知识点分类、人工校对、选区重切和确认入库。
7. 实现题目版本、题型校验、审核发布和基于课本/知识点的检索。
8. 实现组卷规则、候选池、自动组卷、预览、手动替换和快照。
9. 实现本地 PDF 排版、教师版/答案版导出和导出质量检查。
10. 补齐自动化测试、备份恢复、部署脚本和操作文档。

## 16. 第一阶段验收标准

- 可在断网环境中导入 PDF、PNG/JPG 图片和 `.docx` 文件；OCR 和解析过程不调用外部网络服务。
- 导入任务能展示原始页面、OCR 文本、识别区域和题目候选；用户可以修改文本、拖动边界、手动划线或框选、合并和拆分候选。
- 系统不会在人工确认前将自动切题或自动分类结果写入正式题库；确认后生成题目草稿，并保留完整来源链路。
- 题目可以按课本、章节、知识点及其子节点、题型、难度和关键字组合检索。
- 组卷可以按题型、题量、分值和难度分布生成结果；无满足条件的候选时清楚提示缺口。
- 组卷预览支持题目删除、添加、排序、手动替换和分值调整，并实时更新统计信息。
- 试卷可以生成 A4 中文 PDF，分页、题号、选项、图片、页眉页脚和答题区域不重叠、不截断；教师版和答案版权限分离。
- 已确认的试卷使用固定快照，题库后续修改不会改变已生成的 PDF。

## 17. 待确认事项

- 是否需要多租户；若需要，所有业务表需从第一天带上 `tenant_id`。
- 认证是否接入已有 SSO，还是由系统自建账号体系。
- 题目富文本格式选择 Markdown、HTML 白名单还是编辑器专用 JSON。
- 多选题是否支持部分得分、负分和选项乱序。
- OCR 默认使用 PaddleOCR 本地模型还是 Tesseract；是否需要同时支持两者。
- 需要支持的学科、年级、课本版本和知识点目录由谁维护，是否提供初始目录导入模板。
- PDF 是否需要答题卡、密封线、装订线、双栏排版或特殊考试模板。
- 是否需要识别数学公式、化学式、表格和手写内容；这些能力会显著影响本地模型和人工校对范围。
- 组卷难度分布按题目标签、人工等级还是模型估计值计算。
- 是否需要题目内容和附件的操作留痕、脱敏及版本对比页面。
- SQLite FTS5 是否作为第一阶段全文检索实现；默认使用 SQLite 查询和 FTS5，不接入 Elasticsearch/OpenSearch。

在以上事项确认前，建议以单租户、SQLite 查询与 FTS5、PaddleOCR 本地模型、规则优先的自动切题、人工确认知识点、A4 单栏教师版 PDF、客观题全对得分、HTML 白名单富文本作为默认实现假设，并将其集中配置，避免散落在业务代码中。任何新增外部中间件都必须先经过部署约束评审，并提供不依赖该中间件的本地运行方式。
